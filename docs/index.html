FundiLink API (1.4.0)

Download OpenAPI specification:

API for FundiLink, a platform connecting employers who need short-term casual work done with verified local workers ("fundis"). Employers post jobs, workers apply to them (a "booking"), and employers track and update each booking's status.

Authentication: every endpoint needs an API key in the X-API-Key header. A missing or wrong key gets 401. Each consumer gets its own key from our team, sent privately. GET / (health check) is the only open path. POST /users/login only checks a user's email and password; it is not how you authenticate to the API and does not issue a token.

Rate limit: 100 requests per minute per key. Going over returns 429 with a Retry-After header (seconds to wait) and a JSON body.

Errors: every failed request returns JSON with an error message. Validation failures (400) also include a details array listing each problem. Check the HTTP status code first: 2xx is success, anything else is a failure.

Versions: the paths below are v1. They also answer at /v1/..., and every v1 response carries Deprecation: true, Sunset: Fri, 20 Nov 2026 and a Link header pointing to v2. v2 (/v2/users, /v2/jobs, /v2/bookings, …) has the same endpoints, but wraps successful responses: lists become { "data": [...], "count": N } and single items become { "data": {...} }. Errors are the same in both. See DEPRECATION_NOTICE.md.

Monitoring: GET /stats returns request totals, the error rate and per-route timings. Every request is logged as one JSON line, with no keys and no query strings.

Partner

Data from our partner NyumbaHub, fetched by our server

Homes on NyumbaHub that need a fundi (no key needed)

Rentals on our partner NyumbaHub that were just vacated or newly listed, with area and size. Our server calls NyumbaHub (/listings, then /listings/{id}/location and /size for up to 10 homes) using the key NyumbaHub issued us; that key never reaches the caller. Open without a FundiLink key because our own web page calls it; limited to 30 requests a minute per IP. No landlord contact details are returned.

Users

Worker and employer accounts

Search users (e.g. find verified plumbers in Westlands)

All filters are optional and can be combined. With no filters, every user is returned. Results leave out email so a caller can't collect every user's email in one request; use GET /users/{id} for a full profile.

Authorizations:
ApiKeyAuth
query Parameters
role
string
Enum: "worker" "employer"
Example: role=worker

Filter by account type.

trade
string
Example: trade=plumbing

Filter workers by trade (exact match).

location
string
Example: location=Westlands

Filter by location (partial match, case-insensitive).

verified
boolean
Example: verified=true

Only verified (true) or only unverified (false) accounts.
